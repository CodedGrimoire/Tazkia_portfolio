1     Introduction
This report presents Lab Experiment 1 for CSE-4255: Introduction to Data Mining and
Warehousing. The experiment focuses on Online Analytical Processing (OLAP) analy-
sis over the Microsoft WideWorldImportersDW data warehouse. The analysis will use
dimensional-model concepts, including fact tables, dimension tables, measures, hierar-
chies, and OLAP operations.


2     Dataset Collection
The dataset used in this experiment is Microsoft WideWorldImportersDW, a moderate-
sized official Microsoft data warehouse sample obtained from the authenticated Microsoft
Learn catalog. It models business activities such as sales, purchasing, inventory move-
ment, and stock holding. The warehouse contains multiple fact and dimension tables,
making it suitable for studying dimensional modeling and performing OLAP analysis.


3     Database Environment
The WideWorldImportersDW database is restored locally in SQL Server 2022 running
in Docker on macOS. The SQL Server container is named sqlserver, and the database
is named WideWorldImportersDW. The database tool connection uses server localhost
with the sa user. Queries for the experiment will be executed inside the running Docker
container using the SQL Server command-line client.

4.4      Schema Classification
The complete warehouse is best classified as a fact constellation (galaxy) schema
composed of several related star-like subject areas. The classification follows from the
verified metadata: six fact tables share conformed dimensions such as Date, Customer,
Stock Item, and Supplier, while other facts connect to specialized dimensions such as
Payment Method or Transaction Type. An individual process, such as sales or purchasing,
can be viewed as a star schema around its fact table. At the warehouse level, however, the
presence of multiple interconnected fact tables makes fact constellation the more accurate
overall description. The dimensions are not connected to one another by declared foreign
keys in the inspected model, so there is no basis for calling the complete design a snowflake
schema.

4.5      Measures and Measure Classification
The numeric-column inspection separated identifiers, keys, flags, and lineage values from
business measures. A stored base measure is not intrinsically distributive, algebraic, or
holistic; the classification depends on the aggregate applied to it. The table below records
common analytical use. Sums and counts are distributive, while averages such as average
unit price are algebraic because they can be computed from distributive summaries (sum
and count). No holistic measure, such as a median, is stored or required by the inspected

supplier, location, or employee perspectives.

5         OLAP Operations
5.1        CUBE Operation
The SQL Server GROUP BY CUBE operation computes aggregations for all combinations of the selected dimensions. It therefore returns detailed
rows, subtotals for each dimension, and a grand-total row. In the grouped dimension columns, NULL values can indicate a subtotal or grand
total rather than a missing business value. The queries below replace those generated NULL values with explicit labels such as ALL YEARS and
ALL COUNTRIES.

The queries use the verified surrogate-key joins documented in the schema section. The GROUPING() function identifies whether a column was
aggregated by CUBE; consequently, it distinguishes a CUBE subtotal from an actual nullable dimension value. GROUPING ID() is returned as
a compact indicator of which dimensions are aggregated: zero denotes a detailed row, while larger values identify subtotal or grand-total
combinations.


5.1.1       CUBE Query 1: Sales by Calendar Year and Country
Objective. Compare sold units and profit by invoice calendar year and country, including yearly, country, and overall totals.

SQL Query.

SELECT CASE WHEN GROUPING(d.[Calendar Year]) = 1 THEN ’ALL YEARS’
           ELSE CAST(d.[Calendar Year] AS varchar(10)) END AS [Calendar Year],
      CASE WHEN GROUPING(c.[Country]) = 1 THEN ’ALL COUNTRIES’
           ELSE c.[Country] END AS [Country],
      SUM(s.[Quantity]) AS [Units Sold], SUM(s.[Profit]) AS [Profit],
      GROUPING_ID(d.[Calendar Year], c.[Country]) AS [Grouping ID]
FROM [Fact].[Sale] s
JOIN [Dimension].[Date] d ON s.[Invoice Date Key] = d.[Date]
JOIN [Dimension].[City] c ON s.[City Key] = c.[City Key]
GROUP BY CUBE(d.[Calendar Year], c.[Country])
ORDER BY GROUPING_ID(d.[Calendar Year], c.[Country]),
        d.[Calendar Year], c.[Country];

5.2        ROLLUP Operation
ROLLUP generates hierarchical subtotals from the most detailed grouping level toward progressively higher aggregation levels and finally a grand
total. The order of expressions inside ROLLUP matters: the first expression is retained longest, while later expressions are removed as the result
rolls upward. The following five experiments use different fact processes and label generated subtotal rows with GROUPING() or GROUPING ID().

5.3        Drill-Down Operation
Drill-down moves from summarized data to progressively finer levels of detail. Unlike a slice, it changes the grouping granularity: the same
measure is first viewed at a high level, then at a lower level, and finally at an even more detailed level where appropriate.


5.3.1       Drill-Down Experiment 1: Sales Year to Month to Date
Objective. Start with annual sales, refine to the twelve calendar months of 2015, and finally inspect the first three January dates. The three
executed queries were the following.

SELECT d.[Calendar Year] AS [Year], SUM(s.[Total Including Tax]) AS [Sales Including Tax]
FROM [Fact].[Sale] s JOIN [Dimension].[Date] d ON s.[Invoice Date Key]=d.[Date]
GROUP BY d.[Calendar Year] ORDER BY d.[Calendar Year];

WHERE d.[Calendar Year]=2015

5.4        Slice Operation
A slice fixes one dimension to a single verified value, reducing a multidimensional cube to a smaller analytical view. Each query below
explicitly identifies its sliced dimension and uses a different fact or analytical subject where practical.


5.4.1       Slice Query 1: Calendar Year 2015
Objective and slice condition. Fix Dimension.Date.Calendar Year = 2015 and measure sales units and profit.

SELECT d.[Calendar Year] AS [Year],SUM(s.[Quantity]) AS [Units Sold],SUM(s.[Profit]) AS [Profit]
FROM [Fact].[Sale] s JOIN [Dimension].[Date] d ON s.[Invoice Date Key]=d.[Date]
WHERE d.[Calendar Year]=2015 GROUP BY d.[Calendar Year];

Actual output. 2015, 2,740,266 units, profit 26,957,600.65. Interpretation. All other date members are removed from the view.

Objective and slice condition. Fix Dimension.City.Country = United States and compare order quantity by brand.

SELECT si.[Brand],SUM(o.[Quantity]) AS [Units Ordered]

5.5        Dice Operation
Dice selects a subcube by applying conditions to multiple dimensions or ranges simultaneously. Unlike a slice, each query below constrains
at least two dimensions, and the final query constrains three.




                                                Sunday 4th October, 2026
CSE-4255: Introduction to Data Mining and Warehousing                                                                            21


5.5.1       Dice Query 1: 2015 United States Sales
Dice dimensions and conditions. Calendar Year = 2015; Country = United States.

SELECT d.[Calendar Year] AS [Year],c.[Country],SUM(s.[Total Including Tax]) AS [Sales Including Tax]
FROM [Fact].[Sale] s JOIN [Dimension].[Date] d ON s.[Invoice Date Key]=d.[Date]
JOIN [Dimension].[City] c ON s.[City Key]=c.[City Key]
WHERE d.[Calendar Year]=2015 AND c.[Country]=’United States’
GROUP BY d.[Calendar Year],c.[Country];

Actual output. 2015, United States, 62,090,220.81. This is a two-dimensional time-geography subcube.


5.5.2       Dice Query 2: Novelty Shop Profit in 2014–2015
Dice dimensions and conditions. Calendar Year BETWEEN 2014 AND 2015; Customer Category = Novelty Shop.

SELECT d.[Calendar Year] AS [Year],cu.[Category],SUM(s.[Profit]) AS [Profit]
FROM [Fact].[Sale] s JOIN [Dimension].[Date] d ON s.[Invoice Date Key]=d.[Date]
JOIN [Dimension].[Customer] cu ON s.[Customer Key]=cu.[Customer Key]
WHERE d.[Calendar Year] BETWEEN 2014 AND 2015 AND cu.[Category]=’Novelty Shop’
GROUP BY d.[Calendar Year],cu.[Category] ORDER BY d.[Calendar Year];

Actual output. 2014: 15,734,558.65; 2015: 16,548,367.05. The dice retains only the selected time range and category.


5.5.3       Dice Query 3: 2015 Fabrikam and Litware Purchases
Dice dimensions and conditions. Calendar Year = 2015; Supplier IN (Fabrikam, Inc., Litware, Inc.).

SELECT d.[Calendar Year] AS [Year],su.[Supplier],SUM(p.[Ordered Quantity]) AS [Ordered Quantity]
FROM [Fact].[Purchase] p JOIN [Dimension].[Date] d ON p.[Date Key]=d.[Date]
JOIN [Dimension].[Supplier] su ON p.[Supplier Key]=su.[Supplier Key]
WHERE d.[Calendar Year]=2015 AND su.[Supplier] IN (’Fabrikam, Inc.’,’Litware, Inc.’)
GROUP BY d.[Calendar Year],su.[Supplier] ORDER BY [Ordered Quantity] DESC;

Actual output. Fabrikam, Inc.: 39,609,324; Litware, Inc.: 23,741,191 ordered units.


5.5.4       Dice Query 4: United States Northwind Orders
Dice dimensions and conditions. Country = United States; Stock Item Brand = Northwind.

SELECT c.[Country],si.[Brand],SUM(o.[Total Including Tax]) AS [Order Value Including Tax]
FROM [Fact].[Order] o JOIN [Dimension].[City] c ON o.[City Key]=c.[City Key]
JOIN [Dimension].[Stock Item] si ON o.[Stock Item Key]=si.[Stock Item Key]
WHERE c.[Country]=’United States’ AND si.[Brand]=’Northwind’
GROUP BY c.[Country],si.[Brand];

Actual output. United States, Northwind, 17,022,547.25. The result is a product-geography subcube.


5.5.5       Dice Query 5: 2015 EFT Supplier Invoices
Dice dimensions and conditions. Calendar Year = 2015; Transaction Type = Supplier Invoice; Payment Method = EFT.

SELECT d.[Calendar Year] AS [Year],tt.[Transaction Type],pm.[Payment Method],
      SUM(t.[Total Including Tax]) AS [Transaction Value Including Tax]
FROM [Fact].[Transaction] t JOIN [Dimension].[Date] d ON t.[Date Key]=d.[Date]
JOIN [Dimension].[Transaction Type] tt ON t.[Transaction Type Key]=tt.[Transaction Type Key]
LEFT JOIN [Dimension].[Payment Method] pm ON t.[Payment Method Key]=pm.[Payment Method Key]
WHERE d.[Calendar Year]=2015 AND tt.[Transaction Type]=’Supplier Invoice’ AND pm.[Payment Method]=’EFT’
GROUP BY d.[Calendar Year],tt.[Transaction Type],pm.[Payment Method];

Actual output. 2015, Supplier Invoice, EFT, 484,868,081.11. The three restrictions select a small financial subcube.

5.6        Pivot Operation
The SQL Server PIVOT operator rotates an aggregated dimension into columns. The values placed in each IN list were verified against the live
dimension/date data before execution. Each result below keeps the row dimension readable and the pivoted columns small.


5.6.1       Pivot Query 1: Sales by Country Across Years
Objective. Display annual sales including tax as year columns for each country.

SELECT [Country],[2013],[2014],[2015],[2016]
FROM (SELECT c.[Country],d.[Calendar Year],s.[Total Including Tax] AS [Value]
     FROM [Fact].[Sale] s JOIN [Dimension].[Date] d ON s.[Invoice Date Key]=d.[Date]
     JOIN [Dimension].[City] c ON s.[City Key]=c.[City Key]) src
PIVOT (SUM([Value]) FOR [Calendar Year] IN ([2013],[2014],[2015],[2016])) p
ORDER BY [Country];

Actual output. United States: 52,563,272.64; 57,418,916.89; 62,090,220.81; 25,971,029.11 for 2013–2016. The rows are countries and the
columns are years.

5.7.1       GROUPING SETS
GROUPING SETS explicitly names the aggregation combinations to calculate, rather than requesting every combination generated by CUBE or
only the hierarchy implied by ROLLUP. SQL Server returns the union of the specified grouping sets. The following three verified queries
select complementary combinations.


Grouping Sets Query 1. Sales by country and year, country only, year only, and the grand total.
SELECT CASE WHEN GROUPING(c.[Country])=1 THEN ’ALL COUNTRIES’ ELSE c.[Country] END AS [Country],
      CASE WHEN GROUPING(d.[Calendar Year])=1 THEN ’ALL YEARS’ ELSE CAST(d.[Calendar Year] AS varchar(10))
            END AS [Year],
      SUM(s.[Total Including Tax]) AS [Sales Including Tax],
      GROUPING_ID(c.[Country],d.[Calendar Year]) AS [GID]
FROM [Fact].[Sale] s JOIN [Dimension].[City] c ON s.[City Key]=c.[City Key]
JOIN [Dimension].[Date] d ON s.[Invoice Date Key]=d.[Date]
GROUP BY GROUPING SETS ((c.[Country],d.[Calendar Year]),(c.[Country]),(d.[Calendar Year]),());

Actual output. The query returned 10 rows. Year detail values were 52,563,272.64, 57,418,916.89, 62,090,220.81, and 25,971,029.11; the
grand total was 198,043,439.45.

Grouping Sets Query 2. Supplier totals and the overall purchase total.
SELECT su.[Supplier],SUM(p.[Ordered Quantity]) AS [Ordered Quantity]
FROM [Fact].[Purchase] p JOIN [Dimension].[Supplier] su ON p.[Supplier Key]=su.[Supplier Key]

5.7.2       Top-N and Ranking Analysis
Ranking is useful in OLAP decision support because it orders aggregated entities and can identify leaders without discarding the underlying
dimensions. The queries use SQL Server window functions and were executed against the actual facts.

WITH x AS (SELECT cu.[Customer],SUM(s.[Total Including Tax]) AS [Sales Including Tax]
FROM [Fact].[Sale] s JOIN [Dimension].[Customer] cu ON s.[Customer Key]=cu.[Customer Key]
GROUP BY cu.[Customer]), r AS
(SELECT [Customer],[Sales Including Tax],RANK() OVER (ORDER BY [Sales Including Tax] DESC) AS [Rank] FROM
     x)
SELECT TOP 5 * FROM r ORDER BY [Rank],[Customer];

Actual output. The top five were Unknown 73,037,043.78 (rank 1), Tailspin Toys (Inguadona, MN) 438,689.81 (rank 2), Tailspin Toys
(Minidoka, ID) 427,445.57 (rank 3), Wingtip Toys (Sarversville, PA) 420,001.08 (rank 4), and Tailspin Toys (Long Meadow, MD) 414,934.18
(rank 5).




WITH x AS (SELECT si.[Stock Item],d.[Calendar Year],SUM(s.[Profit]) AS [Profit]
FROM [Fact].[Sale] s JOIN [Dimension].[Stock Item] si ON s.[Stock Item Key]=si.[Stock Item Key]
JOIN [Dimension].[Date] d ON s.[Invoice Date Key]=d.[Date]
GROUP BY si.[Stock Item],d.[Calendar Year]), r AS
(SELECT [Calendar Year],[Stock Item],[Profit],ROW_NUMBER() OVER (PARTITION BY [Calendar Year] ORDER BY [
     Profit] DESC) AS [Rank] FROM x)
SELECT * FROM r WHERE [Rank]<=3 AND [Calendar Year]=2015 ORDER BY [Rank];

Actual output. The top three were 20 mm Double sided bubble wrap 50m, 1,782,960.00; Air cushion machine (Blue), 1,325,973.00; and 32
mm Anti static bubble wrap (Blue) 50m, 1,120,560.00.




WITH x AS (SELECT su.[Supplier],SUM(p.[Ordered Quantity]) AS [Ordered Quantity]
FROM [Fact].[Purchase] p JOIN [Dimension].[Supplier] su ON p.[Supplier Key]=su.[Supplier Key]
GROUP BY su.[Supplier]), r AS
(SELECT [Supplier],[Ordered Quantity],DENSE_RANK() OVER (ORDER BY [Ordered Quantity] DESC) AS [Rank] FROM
     x)
SELECT TOP 5 * FROM r ORDER BY [Rank],[Supplier];

Actual output. Fabrikam, Inc. ranked first with 91,142,279, Litware, Inc. second with 48,626,764, followed by A Datum Corporation 5,076,
The Phone Company 1,730, and Graphic Design Institute 1,442.
